## 4.1 Sequential / lifelong editing at 1K and 5K

Table 1 summarises the shared stream runs on `gpt2-small`. Two things are worth
carrying into the discussion:

- The **end-to-end** rewrite rate (a side-memory hit counts as success) sits
  around 15-17% and *falls* as the stream grows: 17.2% -> 14.78% for the trained
  hypernetwork, 15.1% -> 14.86% for the baseline.
- The **model-only** rewrite rate (the parameters alone) is 0.08%-1%, i.e. the
  parametric channel is effectively not writing in any of these runs. Adding the
  W4 guards that force a first parametric write raises the end-to-end rate to
  97.5% at 5K edits, at the cost of routing almost everything to side memory
  (WRITE 2.6%, ROUTE 97.4%).

So the honest statement for the report is: **the memory channel, not the
hypernetwork, is what makes edits retrievable at these scales.**

## 4.2 Gate ablation (W4, this report's own experiment)

Table 2 and Figures 1-2. Four arms over the same 191-edit / 40-subject stream on
`gpt2-xl`:

- `always_write` is the failure mode: end-to-end retention 0.110.
- `always_route`, `rule_gate` and `learned_gate` all reach 1.000 end-to-end
  retention; pairwise exact McNemar between them returns p=1.0 on every metric,
  so the ablation **cannot** separate them on retention.
- What separates them is the decision itself: gate accuracy against the gold
  action is 0.613 for the rules and 0.424 for the learned gate, which collapses
  to "route everything" (1 WRITE / 190 ROUTE / 0 REJECT, kappa 0.009).
- The reason is measurable, not speculative: `CALMEditor.edit_requests` passes
  `retrieval_context=None`, so all four context features are zero inside the
  stream, and the history is empty at the start of a stream (see 4.3).

Consequence for the design: a conflict gate is worth its complexity for
**record correctness and cost** (it decides what gets written, which is what
the 5K run's 97% route share costs), not for retention at the current write
rate. `always_write`-style gating is the only variant that is clearly harmful.

## 4.3 Offline vs. stream gate quality

Table 3 and Figure 3 score both gates on the same 835-record test split three
ways: with the context and history the data sheet provides, with the real
history but `context=None` (what the stream actually does), and cold start (no
history, no context).

| gate | offline | in-stream | cold start |
|---|---|---|---|
| rule gate | 0.840 | 0.613 | 0.408 |
| learned gate | 0.877 | 0.424 | 0.340 |

The learned gate looks better offline (McNemar p=0.039 in its favour) and
significantly worse in the cold-start condition (p=0.0008 against it). The gap
is a **feature-availability** problem: the classifier's three strongest
`ROUTE` weights are `has_context`, `n_prior_edits` and `prior_same_subject`, and
two of those are constant in the stream.

Two fixes follow directly and are cheap:

1. pass the retrieved context through `edit_requests` (or make the gate accept
   it from the request payload), and
2. train with context dropout plus an explicit "cold start" feature, so the
   classifier degrades to the rule policy instead of collapsing to `ROUTE`.

## 4.4 Threats to validity

- 191 edits / 40 subjects on one backbone: the CIs in Table 4 are wide except
  for the 0.89-gap comparisons.
- Gold actions on CounterFact are derived from how each situation was
  constructed; only the 100-record human pilot is real annotation, where the
  learned gate scores 0.650 and the rules 0.670. Treat 0.65, not 0.88, as the
  realistic ceiling.
- Locality is saturated at 1.000 for every arm because almost nothing is
  written to the weights; it will need re-measuring with the guards on.
- The 1K/5K runs (Table 1) use `gpt2-small` on a different machine from the
  `gpt2-xl` ablation; the two are not directly comparable in absolute terms,
  only in direction.
