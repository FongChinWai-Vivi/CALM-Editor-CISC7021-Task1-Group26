## Block 3 — Acceptance conclusion

### ① Which proposal: **A, conditionally**, with C withdrawn and B rejected as specified

- **C — withdraw.** It asks for coverage ≥ 0.50 *and* NLL ≤ +0.5 with no pairing rule, and the measured stream admits 0.5 edits per 100. Nothing in the repository gets within two orders of magnitude of that coverage with the gate as shipped. Keeping it as a live option only invites a table that quotes one half.
- **B — reject as written.** `hit_total ≥ 0.45` is arithmetically out of reach on this stream: 76 of the 191 edits are gold WRITE (0.398), and a parameter channel cannot hit an edit it never wrote. B can only survive if `hit_total`'s denominator or its "hit" definition changes (for instance memory-backed hits counted in, and the all-edits stream named explicitly). Until that definition is written down, B is not a criterion, it is an aspiration.
- **A — adopt, conditionally.** It is the only one of the three that forces the two coordinates into the same sentence (coverage ≥ 0.50 with NLL ≤ +0.90, or coverage ≥ 0.25 with NLL ≤ +0.35), which is the whole point of the audit. But A cannot be *certified* this round: the coverage coordinate is measurable and measured, the NLL coordinate does not exist in any artefact. So: **A is the criterion; the certificate is pending on T2.**

### ② Admitted per 100 at W=50 — one number, with its basis

**50.7 edits per 100**, obtained at `p_WRITE ≥ 0.25` on the stream-path simulation (`gate_roc_pr.json` → `threshold_sweep_on_stream_simulation`), with precision 0.596 against gold WRITE and gold-WRITE recall 0.720. That is the point where the coverage half of A's first branch (≥ 0.50) is first satisfied; it is quoted as a coverage number only, because the NLL half is unmeasured.

Context for that number, so it is not read as a measurement of the W=50 stream:

| setting | admitted per 100 | source |
|---|---|---|
| Gate as shipped, 191-edit stream, argmax, no threshold | **0.5** (1 of 191) | `w4_ablation_learned_gate.json` → `per_edit`, control row in Table 3b's file |
| Stream-path simulation, argmax (= threshold ≈ 0.5) | 28.0 | `gate_roc_pr.json`, `stream_simulation` |
| Cold-start simulation, argmax (= Table 3 online) | 36.8 | `gate_roc_pr.json`, `cold_start_simulation` |
| Stream-path simulation, `p_WRITE ≥ 0.30` | 47.3 | threshold sweep |
| **Stream-path simulation, `p_WRITE ≥ 0.25`** | **50.7** | threshold sweep, quoted above |
| Stream-path simulation, `p_WRITE ≥ 0.55` (A's second branch, coverage ≥ 0.25) | 24.3 | threshold sweep |

The 0.5-versus-28 gap is itself a finding: the same classifier, fed simulated stream features, admits 56× more edits than the live stream did. Context and prior-edit signals do not explain it (both are already emptied in the simulation), so the remaining explanation must be the distribution of `current_answer` / `current_confidence` or the call path in the live stream. Neither is logged, so this audit stops at "cannot judge" and puts the logging in the fix list (`gate_p_write`, `context_provided`) rather than guessing.

### ③ Must-fix order before any re-calibration

1. **T2 — collect `nll_delta`** (with `param_hit_total` in the same row). Without it, no proposal of A/B/C can be certified and every "pass" is half a pass. Cost: one extra forward pass per edit in a loop that already runs one.
2. **T4 — wire the threshold in and log `gate_p_write`.** Today the thresholds are dead code, so any statement about "the current threshold" is false. After wiring, the sweep above becomes a real curve over the live stream instead of a simulation.
3. **T1-a — window-first verdict** (`defer_window`, `pending_writes`, `Decision.DEFER`), then report the per-edit vs window-first admission rates at the same W, with the ±3 per 100 tolerance. T1-b (real `retrieval_context` in `calm_editor.py`) stays an open cross-team item, not something this work package may patch.
4. **T3 / T5 — already in place**; they are regression-guarded by `check_gate_acceptance.py` and must stay green, otherwise a later re-run silently drops the attribution and the footnotes.
5. **T6 — rewrite the acceptance paragraph** to say A, to carry the number above with its threshold, and to name the missing coordinate in the same sentence.

### Forbidden phrasings, restated because they are the easiest to slip into

- No sentence may describe a gate-internal hit-rate gain as an "end-to-end fix". In this repository the end-to-end number for the gate-internal path is 0.110, and that value is the base model's hit rate, not the writer's (`w4_gate_ablations/docs/w4_immediate_rewrite_diagnosis.md`).
- The closed-form 78.8 % (n=500, out-of-gate, teammate stream) may not be printed in the same row, ratio or sentence as any in-gate number. It is a different stream, a different backbone and a different measurement; the footnote says so on every table.
